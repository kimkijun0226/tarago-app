# 알림 대상 선택 흐름 구현 계획

**목표:** 버스·지하철 × 시간·위치의 네 가지 선택을 지도와 편집·저장·취소까지 일관되게 유지한다.
**구조:** 공유 클라이언트 UI 상태에 메뉴와 지도 선택 요청만 저장한다. 저장된 알림은 기존 TanStack Query를 원본으로 유지한다. 지도 선택 모드에는 일반 하단 패널을 표시하지 않고 대상 선택 전용 패널을 사용한다.
**기술:** Expo 57, React Native, Expo Router, Zustand, TanStack Query, 기존 위치·알림 모듈.

- [x] 메뉴·지도 요청 상태와 대상 선택 취소·완료 경계를 정의한다.
- [x] 공통 알림 화면에서 교통수단과 시간·위치 선택을 유지하고 지도에 전달한다.
- [x] 지도에서 기존 하단 화면을 숨기고 정류소·노선 또는 역·방면을 선택한다.
- [x] 선택 완료는 동일 종류의 초안으로, 취소는 이전 목록으로 돌아간다.
- [x] 지하철 위치 폼·좌표·요일·반경 검증을 추가한다.
- [x] 지하철 위치 저장·감지·접근 알림과 1시간 임시 감시를 서버·기기 양쪽에 연결한다.
- [x] 타입·린트·기존 관련 테스트·양 플랫폼 번들·최종 diff를 검증한다.

제약: 새 의존성·네이티브 프로젝트 파일·새 테스트 파일은 추가하지 않는다. 기존 알림을 임의로 복제하거나 삭제하지 않는다. 실제 기기 푸시·위치·진동은 별도 기기 검증이 필요하다.

## 실행 검증

- 앱 타입 검사·린트·포맷·diff 검사 통과.
- 네 가지 조합, 취소·기본 시각·좌표·기존 알림 종류 복원 관련 임시 assertion 16개 통과.
- 기존 버스 알림 테스트 4개 통과. 서버 빌드·린트·기존 관련 테스트 7개 통과.
- iOS·Android 프로덕션 번들 생성 통과.
- 실제 지도 터치·푸시 수신·백그라운드 위치 감지는 기기에서 확인하지 못했다.
- 전체 앱 테스트의 기존 도착시간 포맷 불일치는 이 작업의 변경 범위에서 제외했다.

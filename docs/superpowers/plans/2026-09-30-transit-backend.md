# TaraGo Transit Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a NestJS API that protects the public-data keys and returns normalized nearby transit places, bus arrivals, and subway arrivals.

**Architecture:** Keep the existing Expo app at the repository root and create an independent NestJS application in `server/`. Provider-specific services own external API calls and normalization; one transit controller exposes stable TaraGo JSON contracts. Use an in-process TTL cache for the MVP and leave persistence, Redis, alerts, and background workers out.

**Tech Stack:** Node.js, TypeScript, NestJS, `@nestjs/config`, built-in `fetch`, Jest/Supertest generated by NestJS

**Spec:** `docs/superpowers/specs/2026-09-30-transit-map-arrivals-design.md`

## Global Constraints

- Public-data keys remain in `server/.env.local`; never expose them to React Native or log them.
- Use `SEOUL_BUS_STATION_INFO_SERVICE_KEY`, `SEOUL_BUS_POSITION_INFO_SERVICE_KEY`, and `SEOUL_SUBWAY_REALTIME_ARRIVAL_API_KEY` exactly as named.
- Do not add a database, Redis, authentication, notifications, or background workers.
- Treat a successful response with no arrivals as valid data, not an exception.
- Return only normalized TaraGo contracts; provider-specific XML/JSON fields stay inside provider services.
- Use the public APIs' current official documentation when implementing request parameters and response fields.

## Review Focus

- Missing or blank environment keys must stop server startup with a variable-specific error; covered in Task 1.
- An encoded/decoded public-data key must be encoded exactly once by `URLSearchParams`; covered in Task 3.
- Provider success responses containing zero rows must return an empty array; covered in Tasks 3 and 4.
- Malformed coordinates, radius, station IDs, and station names must return HTTP 400 without calling providers; covered in Task 5.
- Provider failure with cached data must return the cached value with `stale: true`; covered in Task 2 and Task 5.

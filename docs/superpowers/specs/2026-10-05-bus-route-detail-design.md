# TaraGo 버스 노선 상세·실시간 위치 설계

## 사용자 목적과 완료 모습

사용자는 정류장의 버스 번호를 눌러 그 버스가 선택 정류장에 언제 도착하는지, 노선의 어느 구간을 달리는지, 전체 경로와 경유 정류장을 함께 확인한다. 상세 시트는 지도 보기(낮은 위치)와 전체 정류장 목록(높은 위치) 사이를 드래그한다. iOS와 Android에서 같은 정보·상호작용을 제공한다. 알림 설정, 경로 검색, 즐겨찾기는 이 기능에 포함하지 않는다.

## 데이터 신뢰도 원칙

1. 노선 경로는 해당 운행기관이 공개한 **노선 형상 좌표**를 우선한다. 정류장 좌표를 직선으로 연결한 선을 실제 운행 경로처럼 표시하지 않는다.
2. 공식 형상이 없는 지역은 라이선스와 응답 범위를 확인한 외부 노선형상 공급자를 검토한다. 일반 자동차 길찾기 결과는 버스 전용도로·회차·우회를 반영하지 않을 수 있으므로 정확한 버스 노선으로 주장하지 않는다. 검증된 데이터가 없으면 경로 선 대신 정류장 목록과 “지도 경로 준비 중”을 표시한다.
3. 차량 좌표가 공식 API에 있으면 좌표에 표시한다. 정류장 순번만 있으면 해당 정류장/구간에 표시하고 `구간 기준 위치`로 구분한다. 정류장 사이를 임의로 보간해 실시간 GPS처럼 표현하지 않는다.
4. 목표 정류장 ETA는 현재 도착정보 계약을 재사용한다. 회차 추정 ETA는 `예상` 표기를 유지한다. 차량 ID로 도착정보와 위치정보를 연결하되 누락/불일치 때 무리하게 매칭하지 않는다.

## 확인된 데이터 출처

- 경기도: `getBusRouteLineListv2`는 `lineSeq`, `x`, `y`로 공식 노선 형상을 제공한다. `getBusRouteStationListv2`는 정류장 순서·회차 정보를, `getBusLocationListv2`는 차량 ID와 정류장 순번을 제공한다. 기존 서버 공급자가 뒤의 두 API를 이미 일부 사용한다. 출처: https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteLine 및 https://gbis.go.kr/gbis2014/publicService.action?cmd=mBusLocation
- 서울: 공식 버스위치 API는 `tmX`, `tmY` 등 맵매칭 좌표를 명세한다. 전체 노선 형상 제공 여부는 별도 실응답/공식 명세 검증이 필요하다. 출처: https://www.data.go.kr/data/15000332/openapi.do
- TAGO/기타 지역: 경유 정류장 목록과 도착 API의 적용 범위를 노선별로 확인해야 한다. 공식 형상 또는 허가된 외부 형상의 존재를 확인하기 전까지 경로 선을 만들어 내지 않는다.

## 서버 경계와 계약

정류장 UUID와 선택한 `routeId`로 공급자를 판정한다. 같은 노선이 같은 정류장을 두 번 경유하면 도착정보의 정류장 순번(`stationSeq`)까지 선택 식별자에 포함한다. 동일 번호의 다른 노선을 혼동하지 않도록 버스 번호만으로 조회하지 않는다. `routeId`와 순번이 선택 정류장을 실제 경유하는지도 서버에서 검증한다.

- `GET /bus/stations/:stationId/routes/:routeId?stationSeq=...`: 노선 번호·유형, 방향/회차 정류장, 순서가 있는 정류장 목록, 공식 또는 검증된 외부 형상 좌표와 `geometrySource`/`geometryStatus`를 반환한다. 형상은 정적 데이터로 서버에 캐시한다.
- `GET /bus/stations/:stationId/routes/:routeId/vehicles?stationSeq=...`: 차량 ID, 위치 기준(`gps` 또는 `station_segment`), 좌표가 있으면 그 좌표, 없으면 정류장 순번/상태, 공급자 갱신 시각을 반환한다. 같은 노선 동시 요청은 서버에서 합치고 짧게 캐시한다.
- 기존 `GET /bus/stations/:stationId/arrivals`와 동일한 Query 데이터를 상세 화면 ETA에 사용한다. 새로운 ETA 계산기를 만들지 않는다.

응답 필드의 좌표계·시간·숫자 형식은 공급자별로 검증하고 서버에서 정규화한다. 외부 API 키는 서버 밖으로 나가지 않는다. 공식 형상/차량 API 장애 시 오래된 값임을 표시하거나 마지막 유효한 정적 경로를 유지하되, 위치 갱신이 중단된 차량을 현재 위치로 가장하지 않는다.

## 앱 상호작용

1. 정류장 시트에서 노선 행을 누르면 같은 지도 위에 노선 상세 시트가 열린다. 선택 정류장·노선 ID는 화면 상태에만 두고 도착/노선/차량 응답은 TanStack Query가 관리한다.
2. 낮은 시트에는 버스 번호, 선택 정류장 ETA, 새로고침 상태, `전체 정류장` 보기와 닫기를 둔다. 지도는 공식 형상, 선택 정류장, 현재 확인된 차량 위치가 읽히도록 노선 범위에 맞춘다.
3. 시트를 위로 드래그하면 높은 시트에서 순서대로 정류장 목록, 회차점, 선택 정류장 강조, 차량 위치 배지를 보여준다. 위·아래 스냅 위치를 갖고 스크롤과 드래그의 충돌을 피한다. 하단 탭은 상세 표시 동안 숨긴다.
4. 지도 보기로 내리면 기존 카메라로 복귀할 수 있게 하며, 닫으면 선택 정류장 화면으로 돌아간다. 노선을 선택하는 동안 일반 주변 정류장 타일 요청이 불필요하게 증가하지 않도록 한다.

지도 오버레이와 시트 제스처는 이미 설치된 네이버 지도·gesture-handler·Reanimated를 우선 사용한다. SDK 메서드/props는 Expo SDK 57 및 `@mj-studio/react-native-naver-map` 현재 공식 문서를 확인한 다음 구현한다. iOS/Android 네이티브 오버레이 갱신 특성은 두 시뮬레이터에서 확인한다.

## 지역별 도입 순서

1. 경기도 52번으로 공식 형상·정류장 목록·구간 차량 위치·선택 정류장 ETA와 시트 전환을 완성한다.
2. 서울 노선의 공식 형상 출처와 차량 좌표계·실응답을 확인해 같은 응답 계약에 연결한다.
3. TAGO/그 밖의 지역은 공식 형상 우선, 허가된 외부 형상 차선으로 연결한다. 형상 미확보 노선은 선을 생략한다.

이 순서는 지역별 데이터 출처가 다르다는 뜻이며, 최종 UI가 경기도 전용이라는 뜻은 아니다.

## 검증과 실패 기준

- 경기도 52번 노선의 실제 형상점 순서가 공식 응답과 일치하고 정류장 연결 직선이 아닌지 지도에서 확인한다.
- 선택 정류장이 노선에 두 번 등장하면 정류장 ID와 순번을 함께 사용해 올바른 방향을 강조한다.
- 차량 ID로 ETA와 위치를 묶고, 차량이 사라지거나 회차/정류장을 지나면 오래된 위치 마커를 제거한다.
- 공식 ETA, 추정 ETA, 위치 좌표, 구간 기준 위치를 화면에서 구분한다.
- 여러 사용자가 동일 노선을 열어도 외부 노선 형상·차량 API를 사용자 수만큼 호출하지 않는다.
- 시트 낮음/높음·스크롤·닫기·지도 카메라·마커를 iOS와 Android에서 확인한다.
- 서버 테스트/빌드/린트, 앱 타입검사/린트/관련 테스트를 통과한다. 실제 기기/시뮬레이터 확인을 하지 못했다면 완료로 주장하지 않는다.

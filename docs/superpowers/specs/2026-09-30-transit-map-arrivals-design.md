# TaraGo 주변 대중교통 및 실시간 도착정보 설계

## 목표

사용자가 지도에서 주변 버스 정류장과 지하철역을 확인하고, 하나를 선택해 실시간 도착정보를 볼 수 있게 한다. 버스는 노선별 도착 예정정보를, 지하철은 환승역의 호선을 전환하며 방향별 열차 도착정보를 제공한다.

이번 범위에는 알림, 사용자 계정, DB, Background Worker, 경로 검색, 전체 시간표, 첫차·막차 상세, 즐겨찾기, 역 내부·출구 정보를 포함하지 않는다.

## 시스템 경계

공공데이터 인증키를 모바일 번들에 넣지 않는다. React Native 앱은 별도 NestJS API만 호출하며, NestJS가 공공데이터포털과 서울 열린데이터광장을 호출한다.

```text
React Native 앱
  -> TaraGo NestJS API
       -> 공공데이터포털 서울 버스 API
       -> 서울 열린데이터광장 지하철 API
```

모바일 앱은 현재 저장소 루트의 `src/`를 유지한다. NestJS 애플리케이션은 `server/`에 둔다. MVP에서는 DB와 Redis를 추가하지 않는다.

## Backend 구조

`server/src/transit` 아래에 버스와 지하철 책임을 분리한다.

```text
server/src/
├── app.module.ts
└── transit/
    ├── transit.controller.ts
    ├── bus/
    │   └── bus.service.ts
    └── subway/
        └── subway.service.ts
```

초기 API는 세 개다.

- `GET /transit/nearby?latitude={latitude}&longitude={longitude}&radius={meters}`
  - 현재 지도 위치 주변의 버스 정류장과 지하철역을 반환한다.
- `GET /transit/bus-stops/:stationId/arrivals`
  - 선택한 버스 정류장의 노선별 실시간 도착정보를 반환한다.
- `GET /transit/subway-stations/:stationName/arrivals`
  - 선택한 지하철역의 전체 호선 및 방향별 실시간 도착정보를 반환한다.

공공 API의 필드명과 XML/JSON 차이는 서비스 내부에서 변환한다. 앱에는 TaraGo 도메인 타입만 노출한다.

환경변수는 `server/.env.local`에서 읽는다.

- `SEOUL_BUS_STATION_INFO_SERVICE_KEY`: 공공데이터포털 `서울특별시_정류소정보조회 서비스` 일반 인증키의 Decoding 값
- `SEOUL_BUS_POSITION_INFO_SERVICE_KEY`: 공공데이터포털 `서울특별시_버스위치정보조회 서비스` 일반 인증키의 Decoding 값
- `SEOUL_SUBWAY_REALTIME_ARRIVAL_API_KEY`: 서울 열린데이터광장 `서울시 지하철 실시간 도착정보` 전용 인증키

## 공통 위치 데이터

주변 조회 결과는 다음 공통 형태로 정규화한다.

```ts
type TransitPlace =
  | {
      type: "bus-stop";
      id: string;
      name: string;
      latitude: number;
      longitude: number;
      arsId?: string;
    }
  | {
      type: "subway-station";
      id: string;
      name: string;
      latitude: number;
      longitude: number;
      lines: string[];
    };
```

버스 정류장은 위치 기반 정류소 API에서 조회한다. 지하철역 좌표는 실시간 도착 API와 분리된 역 위치 데이터로 관리하며, 실시간 응답은 역 이름과 호선으로 결합한다.

## 지도 동작

앱 시작 시 현재 위치를 구하고 반경 약 700m의 대중교통 위치를 조회한다. 지도 이동 중에는 요청하지 않고 카메라 이동이 끝난 뒤 조회한다. 직전 조회 중심과 충분히 가까운 경우 기존 데이터를 재사용한다.

낮은 확대 수준에서는 지하철역만 표시하고, 가까이 확대하면 버스 정류장과 지하철역을 모두 표시한다. 정확한 확대 기준은 실제 기기에서 마커 밀도를 확인해 결정한다.

현재 React Native 네이버 지도 래퍼는 기본 지도 심벌의 상세 탭 정보를 노출하지 않는다. 따라서 네이버 지도에 보이는 교통 레이어 위에 TaraGo가 관리하는 클릭 가능한 마커를 역과 정류장 좌표에 배치한다. 기본 지도 심벌을 직접 데이터 식별자로 사용하지 않는다.

## 선택 및 Bottom Sheet UX

버스 정류장 또는 지하철역 마커를 선택하면 같은 Bottom Sheet 골격을 사용한다. 선택이 바뀌면 기존 도착정보 쿼리를 중단하고 새 장소의 정보를 조회한다. Bottom Sheet를 닫으면 화면용 Polling을 중단한다.

### 지하철역

상단에는 역 이름과 호선 색상을 표시한다. 환승역이면 `1호선`, `2호선` 같은 호선 탭을 제공하고, 선택한 호선의 정보만 보여준다.

선택한 호선에 대해 이전 역, 현재 역, 다음 역을 노선 색상의 스트립으로 표시한다. 그 아래에는 상행·하행 또는 내선·외선을 두 카드로 분리한다. 카드 제목은 가능한 경우 `광운대 방면`, `신창·광명 방면`처럼 실제 진행 방향을 사용한다.

각 방향 카드에는 가까운 열차 두 대를 표시한다. 남은 시간과 함께 `진입`, `곧 도착`, `급행`, `특급`, `막차` 상태를 표현한다. 마지막 갱신 시각과 수동 새로고침 버튼을 제공한다. Bottom Sheet를 확장하면 추가 열차를 볼 수 있다.

### 버스 정류장

정류장 이름과 정류장 번호를 표시하고, 경유 노선별 첫 번째·두 번째 버스의 도착 예정시간과 운행 상태를 보여준다. 지하철과 동일하게 마지막 갱신 시각과 수동 새로고침을 제공한다.

## 조회 및 캐시 정책

- 주변 정류장·역은 앱 시작 및 의미 있는 지도 영역 변경 시에만 조회한다.
- 버스 도착정보는 Bottom Sheet가 열린 Foreground 상태에서 약 10초마다 갱신한다.
- 지하철 도착정보는 같은 조건에서 약 30초마다 갱신한다.
- 앱이 Background 상태가 되거나 Bottom Sheet를 닫으면 화면용 Polling을 중단한다.
- 수동 새로고침은 즉시 재검증을 요청하되 서버의 외부 API 호출 제한을 따른다.

NestJS 서버는 우선 프로세스 메모리 캐시를 사용한다.

- 주변 정류장·역: 최대 5분
- 버스 도착정보: 5~10초
- 지하철 도착정보: 20~30초

동일한 정류장 또는 역에 대한 동시 요청은 같은 캐시 결과를 재사용한다. 다중 서버 인스턴스가 필요한 시점에 Redis로 교체한다.

## 응답과 오류 처리

성공 응답은 데이터와 갱신 상태를 함께 반환한다.

```json
{
  "data": [],
  "updatedAt": "2026-09-30T00:00:00.000Z",
  "stale": false
}
```

외부 API 호출이 실패했지만 이전 캐시가 있으면 캐시를 반환하고 `stale: true`로 표시한다. 캐시도 없으면 일관된 HTTP 오류와 안전한 메시지를 반환한다. 인증키, 외부 API 원문 URL, 내부 오류 상세는 클라이언트 응답과 로그에 노출하지 않는다.

앱은 다음 상태를 구분한다.

- 최초 로딩
- 정상 데이터
- 정상 응답이지만 도착정보 없음
- 오래된 캐시 데이터
- 네트워크 또는 서버 오류
- 위치 권한 거부 또는 위치 서비스 비활성화

도착정보가 없는 상태를 오류로 취급하지 않는다. 기존 데이터 갱신만 실패한 경우 기존 정보를 유지하면서 갱신 실패 상태를 표시한다.

## 상태 관리

서버 데이터인 주변 장소와 도착정보는 TanStack Query가 관리한다. 선택된 장소, 선택된 지하철 호선, Bottom Sheet 열림 상태 같은 화면 상태는 Zustand 또는 컴포넌트 로컬 상태가 관리한다. 서버 데이터를 Zustand에 복제하지 않는다.

## 검증

- 실제 인증키로 주변 버스 정류장 조회
- 실제 정류장 하나의 도착정보 조회
- 실제 지하철역 하나의 실시간 도착정보 조회
- 버스 및 지하철 원본 응답 변환 단위 테스트
- 도착정보 없음, 외부 API 오류, 잘못된 역 이름 테스트
- 캐시 적중 및 만료 테스트
- 앱의 로딩, 빈 결과, stale, 오류 표시 확인
- iOS와 Android에서 마커 선택, 호선 전환, Bottom Sheet 동작 확인
- 앱과 서버의 린트 및 타입 검사

## 구현 순서

1. `server/`에 NestJS 애플리케이션 생성 및 환경변수 검증
2. 공공 API 응답을 직접 확인하는 최소 진단 엔드포인트 작성
3. 버스 정류장 주변 조회와 도착정보 정규화
4. 지하철역 위치 데이터와 실시간 도착정보 정규화
5. 통합 주변 조회 및 메모리 캐시
6. React Native에 TanStack Query 연결
7. 지도 마커 및 선택 상태 구현
8. 지하철·버스 Bottom Sheet 구현
9. Foreground Polling과 앱 상태 연동
10. iOS·Android 실제 동작 검증

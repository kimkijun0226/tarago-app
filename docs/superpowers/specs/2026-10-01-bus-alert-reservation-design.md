# TaraGo 버스 알림 예약 화면 설계

## 목표

사용자가 `알림` 탭에서 버스 도착 알림을 직접 만들고 관리할 수 있게 한다. 지도에서 정류장과 버스를 선택한 경우에도 별도 구현을 만들지 않고 같은 알림 설정 화면을 재사용한다.

이번 설계는 화면 구조와 데이터 흐름을 확정한다. 서버 저장, Monitoring Worker, Push Notification은 화면 흐름이 검증된 뒤 순서대로 연결한다.

## 내비게이션

하단 탭은 두 개만 유지한다.

- `지도`: 현재 지도 화면이다. 기존 `Home` 이름을 바꾸고 지도 아이콘을 사용한다.
- `알림`: 기존 템플릿 `Explore` 화면을 제거하고 알림 목록 화면으로 교체한다.

알림 설정은 하단 탭이 아니라 탭 위에 열리는 별도 Stack 화면으로 둔다. 이를 위해 Expo Router 구조를 다음과 같이 정리한다.

```text
src/app/
├── _layout.tsx
├── (tabs)/
│   ├── _layout.tsx
│   ├── index.tsx
│   └── alerts.tsx
└── alerts/
    └── new.tsx
```

- 루트 `_layout.tsx`: 공통 Provider와 Stack을 담당한다.
- `(tabs)/_layout.tsx`: `지도 | 알림` NativeTabs를 담당한다.
- `alerts/new.tsx`: 알림 생성 화면이다.

## 진입 경로

### 알림 탭에서 직접 생성

1. 사용자가 `알림` 탭을 연다.
2. `새 알림 만들기`를 누른다.
3. 알림 설정 화면에서 정류장을 검색해 선택한다.
4. 해당 정류장의 경유 또는 도착 예정 버스 중 하나를 선택한다.
5. 요일, 감시 시작·종료 시간, 알림 기준을 설정한다.
6. 저장하면 알림 목록으로 돌아간다.

### 지도에서 생성

1. 사용자가 지도에서 정류장 마커를 선택한다.
2. BottomSheet에서 원하는 버스를 선택한다.
3. `도착 알림 만들기`를 누른다.
4. 같은 알림 설정 화면으로 이동한다.
5. 정류장과 버스는 미리 선택되어 있고 나머지 조건만 설정한다.

지도 진입은 다음 값만 URL parameter로 전달한다.

```ts
type NewAlertParams = {
  stationId?: string;
  stationName?: string;
  routeId?: string;
  busNumber?: string;
};
```

서버 응답 객체 전체를 URL이나 Zustand에 복제하지 않는다. 설정 화면은 전달받은 ID를 기준으로 필요한 서버 데이터를 TanStack Query에서 조회한다.

## 알림 목록 화면

`알림` 탭은 다음 상태를 구분한다.

- 저장된 알림이 없음: 설명과 `새 알림 만들기` 버튼
- 로딩 중
- 저장된 알림 목록
- 서버 오류와 재시도

각 목록 항목은 다음 정보를 보여준다.

- 버스 번호
- 정류장 이름
- 적용 요일
- 감시 시작·종료 시간
- 알림 기준
- 활성화 Toggle

항목을 누르면 같은 설정 화면을 편집 모드로 연다. 삭제는 상세 화면에서 제공하며 이번 첫 UI 단계에는 포함하지 않는다.

## 알림 설정 화면

입력 순서는 다음과 같다.

1. 정류장
2. 버스
3. 요일
4. 감시 시작 시간
5. 감시 종료 시간
6. 알림 기준 (`10분`, `5분`, `3분`, `1분`)
7. 활성화 여부

기본값은 평일, `07:00~08:00`, `10분·5분`, 활성화 상태다. 최소 한 요일과 한 알림 기준이 필요하다. 종료 시간이 시작 시간보다 이른 경우 다음 날로 넘기지 않고 입력 오류로 처리한다. 자정 경계 감시는 MVP에서 제외한다.

정류장을 변경하면 기존 버스 선택을 초기화한다. 버스 선택지는 선택한 정류장의 서버 도착정보 또는 경유 노선 API에서 가져온다. 현재 도착정보가 없더라도 노선 선택이 가능해야 하므로 최종적으로는 정류장 경유 노선 API를 별도로 사용한다.

## 상태 관리

- TanStack Query: 정류장 검색, 정류장 경유 버스, 저장된 알림 목록, 알림 생성·수정
- 로컬 React state: 아직 저장하지 않은 설정 폼 입력값
- Zustand: 여러 화면에서 공유해야 하는 지도 UI 상태가 생겼을 때만 사용

서버 데이터를 Zustand에 복제하지 않는다. 초기 단계에서는 폼 라이브러리를 추가하지 않고 React state와 작은 검증 함수로 구현한다.

## 서버 계약 초안

화면 검증 후 NestJS에 다음 API를 추가한다.

```text
GET    /bus/stations/search?query={keyword}
GET    /bus/stations/:stationId/routes
GET    /alerts
POST   /alerts
PATCH  /alerts/:alertId
DELETE /alerts/:alertId
```

알림 생성 요청은 다음 형태다.

```ts
type CreateBusAlertRequest = {
  stationId: string;
  routeId: string;
  busNumber: string;
  daysOfWeek: number[];
  startTime: string;
  endTime: string;
  thresholds: number[];
  enabled: boolean;
};
```

`daysOfWeek`는 `1=월요일`부터 `7=일요일`까지 사용한다. 시간은 사용자 지역의 `HH:mm` 문자열로 받고, 사용자 시간대 저장 방식은 인증 도입 시 확정한다.

## 오류 처리

- 정류장 검색 실패와 버스 목록 실패를 폼 전체 오류로 합치지 않는다.
- 도착정보가 없는 상태는 오류가 아니다.
- 저장 실패 시 입력값을 유지하고 다시 시도할 수 있게 한다.
- 지도에서 전달받은 정류장 또는 노선 ID가 유효하지 않으면 해당 선택만 비우고 직접 선택을 안내한다.

## 구현 순서

1. Expo Router를 Root Stack + `(tabs)` 구조로 정리한다.
2. `Home`을 `지도`로 바꾸고 지도 아이콘을 적용한다.
3. `Explore`를 제거하고 `알림` 빈 목록 화면을 만든다.
4. `새 알림 만들기` 버튼으로 `alerts/new` 화면을 연다.
5. 알림 설정 UI와 입력 검증을 만든다.
6. 지도 BottomSheet의 버스 항목에서 설정 화면으로 이동하고 값을 미리 채운다.
7. 정류장 검색과 경유 노선 API를 NestJS에 추가한다.
8. PostgreSQL 알림 저장 API를 추가하고 TanStack Query로 연결한다.
9. Monitoring Worker와 Push Notification을 연결한다.

## 첫 구현 범위

다음 구현에서는 1~4번만 진행한다. 즉, 내비게이션 구조와 `지도 | 알림`, 빈 알림 목록, 알림 설정 화면 진입까지만 만든다. 폼과 서버 저장을 한 번에 구현하지 않는다.

## 완료 조건

- iOS와 Android에서 하단 탭이 `지도 | 알림` 두 개만 보인다.
- 지도 탭은 기존 지도와 정류장 BottomSheet 동작을 유지한다.
- 알림 탭의 `새 알림 만들기`를 누르면 별도 설정 화면으로 이동한다.
- 설정 화면에서 뒤로 가면 알림 탭으로 돌아온다.
- 앱 테스트, 타입 검사, 린트가 통과한다.

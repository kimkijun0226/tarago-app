# 타라고 알림 화면

Airbnb의 밝은 배경, 둥근 요소, 명확한 정보 위계를 참고한다.
참고: https://getdesign.md/design-md/airbnb/preview

## 디자인

- 배경 #FFFFFF, 보조 표면 #F7F7F7/#F2F2F2, 본문 #222222, 보조 글자 #6A6A6A. 지도·알림·검색·상세·탭은 `shared/ui/theme.ts`의 같은 팔레트를 공유한다.
- 브랜드 코랄 #FF385C, 눌림 #E00B41, 연한 테두리 #FFD1DA, 선택 표면 #FFF7F8를 사용한다. 작은 글자와 흰 CTA 글자는 대비를 확보한 #D92850를 사용한다. 보조 팔레트는 Luxe #460479, Plus #92174D, 링크 #428BFF, 오류 #C13515이며 필요에 맞는 의미로만 사용한다.
- 카드 모서리 20, 화면 여백 24, 제목과 설명 간격 4, 터치 영역 최소 44.
- 버스·지하철 × 시간·위치의 네 가지 종류를 같은 페이지에서 선택한다. 선택한 종류는 지도·초안·저장·취소까지 유지한다.
- 목록 카드는 대상 → 도착 기준/반경 → 요일·시간 → 상태 → 수정·삭제 순서다.
- 비활성 알림은 흐린 글자 대신 상태 문구와 연한 표면으로 구분한다.

## 책임

- theme.ts / map-design-tokens.ts / alert-design.ts: Airbnb 공통 팔레트와 기능별 호환 토큰. alert-screen-styles.ts는 알림 영역의 시각 규칙을 담당한다.
- alert-components.tsx: 페이지 헤더, 저장 카드, 선택 칩, 요일, 안내, 기본 버튼.
- alert-schedule-fields.tsx: 버스·지하철 공통 요일·시간·도착 기준·단계 입력.
- alert-editor-form.tsx / subway-alert-editor.tsx: 교통수단별 입력과 선택 대상의 도착정보.
- use-alert-screen.ts / use-subway-alert-screen.ts: 로컬 초안, 권한 확인, 저장·삭제·토글.
- alert-form.ts: 초안 타입과 순수 입력 검증. 서버 상태는 기존 TanStack Query 훅에 둔다.
- alerts-screen.tsx / subway-alert-panel.tsx: 공통 화면과 교통수단별 입력·목록 조립.

## 동작

- 저장된 알림 편집 시 종류 전환으로 ID를 제거하지 않는다. 목록 필터와 새 알림 종류 선택을 구분한다.
- 기존 시간·위치 복합 알림은 하나의 ID로 두 조건을 보존하며 저장한다. 복제·삭제 마이그레이션은 하지 않는다.
- 위치 전용 알림은 요일·반경·재알림 간격(1·3·5·10분, 기본 5분)을 검증한다. 숨긴 예약값은 서버 계약에 맞게 보존하거나 기본값을 넣는다.
- 시간 알림은 요일, 서로 다른 시작·종료 시각, 1~30분 기준, 유효한 알림 단계를 검증한다. 자정 넘김은 허용한다.
- 기준 분 변경 시 선택한 기준 단계를 옮기고 범위를 넘는 단계만 제거한다. 기존 사용자 지정 단계도 표시한다.
- 저장·토글·삭제·연결 중에는 중복 조작과 폼 수정을 막는다.
- 버스 미리보기는 정류소의 모든 노선이 아닌 선택한 노선·정류소 순번만 표시한다.
- 지하철도 시간·위치 알림을 지원한다. 위치 알림은 역 좌표·접근 반경·요일·재알림 간격을 저장하고 반경 안에서 앞선 두 열차의 도착정보를 반복 안내한다.

## 검증 범위

프로젝트 지침에 따라 새 테스트 파일을 추가하지 않는다. 타입 검사, 린트, 기존 관련 테스트와 임시 순수 함수 검증을 사용한다. 실제 푸시 수신과 백그라운드 위치 감지는 기기에서 확인해야 한다.

## 간결한 설정 화면

- 안내용 제목·설명·목록 개수와 상시 오류 설명문은 생략한다. 빈 목록과 조회 실패는 별도 상태로 처리하며 빈 목록에 오류를 표시하지 않는다. 연결 실패는 접근성 레이블이 있는 작은 재시도 아이콘으로 표시한다.
- 반복 요일 선택 → 왼쪽 시작·오른쪽 종료 → 도착 알림 순서로 배치한다.
- 시간 필드를 누르면 iOS 네이티브 휠을 하단에 표시한다. Android는 네이티브 시간 다이얼로그를 사용한다.
- 도착 기준은 숫자 입력과 알림 시점 칩으로 구성하고 중복 프리셋과 설명을 없앤다.

## 빈 상태와 아이콘

- 알림이 없으면 실제 목록 카드와 같은 최소 높이(240)의 점선 카드 안에 둥근 + 아이콘과 ‘지도에서 선택해주세요’를 표시한다.
- 추가 버튼은 지도로 연결한다. 빈 응답과 요청 실패를 혼동하지 않으며 실패 시에는 헤더의 새로고침 아이콘으로 연결 상태를 표시한다. 새로고침은 목록 오른쪽 위 한 곳에만 둔다.
- 추가·뒤로·지도·수정·삭제·새로고침·시간 선택 완료는 둥근 아이콘 버튼을 사용한다. 접근성 이름은 유지한다.

## 대상 선택 흐름

1. 알림에서 버스/지하철과 시간/위치를 고른다.
2. 추가 카드를 누르면 해당 종류가 고정된 지도 선택 모드로 진입한다.
3. 지도에서는 검색·내 위치와 알림 대상 선택 패널을 제공한다. 검색 입력·결과가 열린 동안 선택 패널을 잠시 숨긴다.
4. 버스는 정류소 → 노선·경유 순번, 지하철은 역 → 호선·방면을 선택한다. 확인된 좌표만 위치 알림에 사용한다.
5. 완료하면 같은 종류의 편집 화면으로 돌아간다. 뒤로가기 또는 Android 뒤로가기는 선택을 취소하고 이전 메뉴로 돌아간다.
6. 저장된 알림이 있는 목록에도 작은 추가 카드를 남겨 다음 알림을 만들 수 있다.

## 지하철 위치 감시

- 서버 JSON 설정에 모드·좌표·반경을 보관하며 기존 시간 알림은 기본 시간 모드를 유지한다.
- 버스와 지하철의 감지 영역을 한 작업에 합쳐 총 20개 제한을 적용한다.
- 역 반경에 들어오면 앞선 두 열차의 도착정보를 즉시 안내하고, 선택 간격으로 반복하다가 반경을 벗어나면 멈춘다. 별도 감시 세션은 만들지 않는다.
- 기존 소유권·요일·권한·기기 저장소 검사를 유지한다. 실제 기기의 위치 감지와 푸시 수신 검증은 별도다.

## 지하철 방면과 행선지

- 화면에서는 상행·하행 코드 대신 확인된 다음 역의 ‘○○역 방면’을 표시한다.
- 알림 카드와 선택 패널에는 해당 방향의 실제 행선지 ‘△△행’도 표시한다.
- 인접역과 실시간 방면을 대조하고, 순환·지선의 다음 역을 종착역으로 추측하지 않는다.
- 표시 메타데이터(nextStationName, destinationNames)는 감시 필터(destination)와 구분한다. 표시 때문에 다른 행선지 열차를 제외하지 않는다.
- 서버 푸시의 제목·본문은 실제 감지한 열차의 행선지를 사용한다.

### 지하철 알림 지도 전용 스타일

- 지하철 알림 추가 모드에만 `EXPO_PUBLIC_SUBWAY_MAP_STYLE_ID`를 적용한다. 일반 지도에는 기본 스타일을 사용한다.
- 지하철 알림 추가 모드에서는 별도 배지·마커·글자를 만들지 않고 네이버 기본 지도 심벌을 줌 14 이하에서 1.3배로 표시하고 줌 14~15 사이에서는 확대 비율을 줄이며 줌 15 이상에서는 기본 크기로 표시한다. 일반 지도는 1배다. 알림 대상 선택 시 버스는 줌 16, 지하철은 줌 15를 사용한다. SDK 배율은 모든 심벌에 적용되며, 역 표시의 최소 노출 줌은 별도 제어할 수 없어 축소 시 노출 범위 확장은 미해결이다. 다른 장소 숨김은 발행된 전용 스타일 ID가 있어야 적용된다.
- 네이버 Map Style Editor에서 라이트 스타일을 만들고 지하철역 심벌만 유지한다. 산·아파트·도서관·상점·버스정류장 등 나머지 장소 심벌은 가시화를 끄되 도로·하천·지하철 노선은 유지한다. 스타일 자체의 심벌 크기는 기본값을 유지한다.
- Save 후 Publish로 발행한 My Style ID를 `.env.local`의 `EXPO_PUBLIC_SUBWAY_MAP_STYLE_ID`에 넣고 Metro를 재시작한다. ID 발행 전에는 기본 지도의 장소 심벌이 남는다.
- 커스텀 스타일 적용 시 레이어 설정은 에디터의 설정을 따르므로 건물·등산 정보도 에디터에서 정리해야 한다.
- 공식 안내: https://guide.ncloud-docs.com/docs/application-maps-styleeditor-edit-vpc 및 https://guide.ncloud-docs.com/docs/application-maps-styleeditor-publish-vpc

### 알림 지도 검색과 현재 위치

- 버스·지하철 알림 추가 지도 진입 시 현재 위치를 다시 조회해 중심을 이동한다. 조회 중 검색이나 대상 선택을 시작하면 늦은 위치 응답이 사용자의 선택을 덮어쓰지 않는다. 버스·지하철 알림 선택 중에도 검색창과 현재 위치 버튼을 제공한다. 버스는 정류장, 지하철은 역으로 검색 결과를 제한한다.
- 검색 입력·결과가 열린 동안 알림 선택 패널을 숨기고, 결과 선택 시 현재 알림 종류를 유지한 채 대상 선택 패널로 돌아간다.
- 검색 닫기는 지도 선택 모드를 유지하고, 지도 뒤로가기는 알림 목록으로 돌아간다.
- 앱의 길찾기 진입 버튼, 출발·도착 편집, 경로 조회 요청과 결과 화면, 길찾기 선·끝점 표시를 제거했다. 버스 노선 상세는 유지한다.

## 귀여운 선택 영역과 공통 화면

- 기존 정보 위계·간결한 문구를 유지하며 새 안내 문장이나 게임 점수·미션을 추가하지 않는다.
- 선택 영역 전체를 터치한다. 별도의 ‘선택’·확인 버튼을 추가하지 않는다. 대상 행 오른쪽은 작고 둥근 화살표로 표시한다.
- 교통수단은 기존 버스·지하철 아이콘을 둥근 영역에, 알림 종류·요일·시간·반경·재알림 간격은 부드러운 코랄 선택 상태로 표시한다.
- 카드 기본 모서리 20, 선택 영역 18~24, 시트 28을 사용한다. 선택 상태는 분홍 표면과 코랄 테두리, 얕은 아래쪽 두께로 구분한다.
- 누름 효과는 작은 내려감·축소로 제한한다. 장식 배지나 새 지도 마커는 만들지 않는다.
- 제목과 보조 글자 간격 4, 기존 최소 터치 높이 44, 긴 이름의 줄바꿈·생략 처리를 유지한다. 7개 요일은 좁은 화면에서도 한 줄로 배치한다.
- 실제 버스 노선 유형·지하철 호선의 공식 색은 유지한다. 검색 아이콘·행동·선택 상태는 공통 코랄을 사용한다.
- 시작 화면의 코랄 배경은 `app.json`에 반영한다. 네이티브 시작 화면 설정은 새 빌드에 반영된다.

## 헤더와 알림 내역 규칙

- 헤더의 아이콘은 배경·테두리·박스·캡슐로 감싸지 않는다. 보이는 것은 아이콘 자체뿐이며 터치 영역은 최소 44를 유지한다.
- 헤더 새로고침 버튼과 당겨서 새로고침은 사용하지 않는다. 화면 진입·앱 복귀·알림 수신 시 자동 갱신한다.
- 알림 내역 진입은 종 아이콘을 사용하고 읽지 않은 새 내역이 있으면 작은 점을 표시한다. 내역 화면에서 확인한 최신 항목까지만 읽음 처리하며 이후 도착한 항목은 계속 안 읽음으로 남긴다.
- 알림 내역의 빈 상태는 종 아이콘만 보여준다. ‘알림 내역을 불러오지 못했어요’, ‘아직 알림 내역이 없어요’ 같은 설명글을 화면에 추가하지 않는다. 빈 상태와 실제 조회 오류의 원인·상태는 코드와 접근성 레이블에서 구분한다.

- 알림 푸시·내역·저장 카드의 대상 영역을 누르면 해당 버스 정류장/노선 또는 지하철역으로 이동한다. 수정 화면은 명시적인 수정 아이콘에서만 연다.

- 알림 생성·수정 시 시간 알림과 위치 알림을 독립적으로 선택해 둘 다 사용할 수 있다. 최소 한 종류를 유지하고 저장 시 실제 선택 상태를 보존한다. 지하철 시간 알림에 위치 알림을 추가할 때는 공식 역·호선 좌표를 확인한다.
- 노선에서 다른 정류소를 선택하면 노선 선을 해제하고 선택 정류소의 전체 버스 목록을 연다.

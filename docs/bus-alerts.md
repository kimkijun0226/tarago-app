# 버스 알림의 종류와 실행 흐름

정류장 목록의 종 버튼으로 정류장·노선을 선택해 설정한다. 목록에서는 편집·활성화·삭제를 제공한다.
각 파일의 JSDoc은 입력·상태·이벤트 처리 역할을 기술한다.

## 세 가지 상태

### 버스 시간 알림

요일과 한국 시간 기준 시작·종료 시각에 따라 서버가 도착정보를 감시한다.
위치 접근 여부를 조건으로 사용하지 않는다. 종료 시각이 시작보다 이르면 다음 날까지 이어진다.
도착정보가 없더라도 활성 감시 범위 안에서는 다시 조회한다.

최대 두 차량의 정보를 한 알림에 담고 첫 번째 차량의 알림 단계가 바뀔 때 갱신한다.
기본 단계는 5·3·2·1분·곧 도착이며 사용자가 단계와 차량번호 표시 여부를 선택할 수 있다.
처음 관측한 값이 1분이라면 지난 단계를 한꺼번에 보내지 않는다.
번호판은 공급자가 제공하는 실제 값만 사용한다. 알림을 누르면 해당 정류장 화면으로 이동한다.

### 위치 기반 접근 알림

선택한 요일에 선택 정류장에 접근하면 해당 노선의 현재 도착정보와 함께 **1시간 감시를 시작할지** 묻는다.
선택 가능한 반경은 100·200·300·500m다. 사용자 동의 없이 도착 감시를 시작하지 않는다.
지오펜스와 foreground 위치 확인은 기기에서 동작하며, 정류장에 머무르는 동안 같은 제안을 계속 보내지 않도록 방문 상태를 기억한다.

이 기능에는 알림 권한과 백그라운드 위치 권한이 필요하다. 시간 알림에는 이 위치 권한을 요구하지 않는다.
GPS 정확도와 OS 절전 정책에 따라 실제 접근 감지가 지연될 수 있다.

### 별도 1시간 감시

접근 제안에 동의하면 시간 예약 목록과 구분되는 감시 세션으로 저장한다.
만료 때 알림에서 1시간 연장 또는 종료를 선택할 수 있다. 감시를 종료해도 원래 접근 설정 자체를 삭제하지 않는다.
다음 실제 재진입과 방문 상태에 따라 다시 시작을 제안한다.

## 파일의 책임

- `src/app/(tabs)/alerts.tsx`: URL 파라미터와 저장된 알림으로 최초 초안 구성.
- `ui/alerts-screen.tsx`: 전달받은 초안의 목록·편집·저장·권한 준비 연결.
- `ui/alert-editor-form.tsx`: 요일·시간·반경·알림 단계 입력과 도착 미리보기.
- `ui/monitoring-sessions-panel.tsx`: 진행 중인 1시간 감시의 연장·종료 UI.
- `model/use-alerts.ts`: Query 조회·mutation·저장 후 캐시 반영.
- `api/alerts.ts`: SecureStore 기기 인증과 타라고 서버의 알림 API.
- `model/use-monitoring-sessions.ts`: 세션 생성·연장·중지와 OS의 만료 확인 알림 예약.
- `model/use-alert-runtime.ts`: 루트의 위치 구독과 푸시 응답에 따른 화면 이동.
- `model/alert-runtime.ts`: React 밖의 백그라운드 작업·권한·푸시 등록·지오펜스 연결.
- `model/bus-alert.ts`: 알림 입력 계약·거리·시간·방문 판정과 접근 문구.
- `model/alert-storage.ts`: 백그라운드 접근 감지에 필요한 기기 사본 저장.

`src/app`을 제외한 위 경로는 `src/features/bus-alert` 기준이다. 기기 사본은 위치 작업용이며 화면의 서버 상태 원본은 Query다.
실제 버스 도착 감시와 푸시 발송은 별도 서버 Worker가 수행한다.

## 실행 경계

`AlertRuntime`은 루트에서 `useAlertRuntime()`을 실행해 위치·알림·앱 복귀 구독을 유지한다.
오류 상태는 앱 스토어의 `alertRuntimeError`로 공유하며 런타임 수명이 끝나면 초기화한다.
구독 해제 후 끝난 비동기 오류는 스토어에 다시 기록하지 않는다.

푸시 전송은 EAS 프로젝트와 APNs/FCM 자격 증명에 의존한다.
백그라운드 접근 감지는 기기 위치 권한과 OS의 실행 정책에 의존한다.
시뮬레이터 지도 표시나 JS 번들 생성은 실기기 푸시·지오펜스 동작의 검증과 별개다.
